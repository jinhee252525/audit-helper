# 감사 선례 대시보드 구성안 (HITL-B 확인용 초안)

> 대상 파일: `app/dashboard.html` (작동하는 초안). 이 문서는 "무엇을·왜·어떻게 보여줬는지"와
> 사용자가 화면별로 **확정/수정할 항목**을 정리한다. 모든 수치는 `data/findings.json`(9,631건) 실집계.

## 0. 한 줄 요약
분류체계 확정본(권익위 관련기능19·발생분야28 코드북)을 축으로, **실무담당자·제도개선·결재권자**
세 관점을 탭으로 나눈 단일 페이지 대시보드. 정적 사이트 제약(CDN 없음, 오프라인)에 맞춰
**바닐라 JS + 인라인 SVG**로 클라이언트에서 집계·렌더한다.

핵심 결과:
- **결측을 숨기지 않는다.** disposition·sector는 null을 버리지 않고 "미부과·해당없음"/"미상"

  sector는 92% 결측이므로 성긴축으로 보고 **보조 차트 + 필터**로만 노출(N·미상 명시).

## 2. 화면 구조

```
헤더(면책 안내 배너) → AXIS 탭 3종 → 공용 필터바 → KPI 5카드
   → [탭별 차트 섹션] → 공용 사례 카드 리스트(더보기)
```

### 2-1. AXIS 탭 (사용자별 진입 동선)
- **실무담당자 (AXIS A)**: `업무별 분포`(막대) · `처분종류`(막대) · `근거법령 Top12`(막대).
  → 내 work_type을 필터로 좁혀 "결재 전 유사 지적·처분·법령"을 확인(F2 사전점검 연계).
- **제도개선 (AXIS B)**: `반복지적 Top = work_type × org_type`(누적막대) · `연도 추세`(라인) ·
  `발생분야 보조축`(막대). → 반복도 높은 업무·추세에서 제도개선 과제 발굴(F5 연계).
- **결재권자(요약)**: `소스별` · `기관유형별` 분포 + `지적↔면책 안전판`(F8). → 규모·출처·안전판을 한눈에.

### 2-2. KPI 카드 (5종, 필터 연동)
총 건수(전체 대비) · 유형 구성(지적/컨설팅/면책) · 처분 기재 건수(+미부과·해당없음) ·
소스 개수(상위 나열) · 최근 연도.

### 2-3. 차트 목록·유형 선택 근거
| 차트 | 유형 | 근거 |
|---|---|---|
| 업무(관련기능)별 분포 | 가로 막대 | 범주 크기 비교(magnitude), 라벨 길어 가로가 유리 |
| 처분종류 분포 | 가로 막대 | 결측을 "미부과·해당없음"으로 한 범주로 노출 |
| 근거법령 Top12 | 가로 막대 | 긴 법령명 가독, 상위 절단 |
| 반복지적 work_type×org_type | 누적 가로 막대 | 반복도(총량)+기관유형 구성 동시 표현. 색=기관유형(dataviz 검증 팔레트) |
| 연도 추세 | 라인 | 시간 변화(change-over-time) |
| 발생분야(보조) | 가로 막대 | 성긴축, 미상 포함해 참고용 |
| 소스별/기관유형별 | 가로 막대 | 구성 비교 |
| 지적↔면책 안전판 | 가로 막대(3범주) | 현재 면책 0 → 데이터 확보 시 대조 강화 |

### 2-4. 필터 (전 차트·KPI·카드 동시 갱신)
관련기능(업무)·처분종류·소스·연도·기관유형·**발생분야(미상 포함)**·검색어(원문·기관명·법령).
검증: `계약 + 국회결산` = 849건으로 차트·카드가 정확히 좁혀짐(파이썬 교차검증 일치).

### 2-5. 사례 카드
`work_type 라벨` + 유형 배지 + 처분 배지(없으면 "미부과·해당없음") + `source_excerpt`(4줄 클램프)
+ 근거법령(현행 "확인 필요" 병기) + 기관명 + **소스·연도·출처 링크(↗)**. 20건씩 더보기.

## 3. 절대 규칙 반영
- "위법·부당" 단정 금지 → 카드 라벨은 **"유사 지적 사례"**, 헤더에 판단 주체 명시.
- 모든 카드에 **출처 링크 + 처분(결측=미부과·해당없음)** 노출.
- 근거 없는 수치 생성 없음 — 전량 findings.json 실집계.
- 법령 현행 여부 **"확인 필요"** 병기.
- 담당자 평가·징계 목적 사용 금지 문구 헤더 고정.
- 접근성: KWCAG 고려(범례+직접 라벨로 색 단독 의존 회피, `<title>` 툴팁, 라이트/다크 대비 토큰).

## 4. 알려진 한계 / 데이터 의존
- **면책(immunity) 0건**: F8 안전판은 현재 지적/컨설팅만. 면책 사례집 태깅 후 자동 채워짐.
- `summary` 전부 null → 본문은 원문 발췌 사용(요약 태깅은 후속).
- 스키마에 `source_title`·`posted_date` 필드 없음 → 카드 출처는 **소스명 + 기관명 + 연도 + source_url**로 구성.
- audit_type 80% 결측 → 대시보드 제외(필요 시 필터로 추가 가능).

## 5. 확정/수정 요청 항목 (사용자 결정 필요)
1. **AXIS 3탭 구성**이 실무 흐름에 맞는가? (담당자/제도개선/결재권자)
2. **반복지적 주차트**를 `work_type×org_type 누적막대`로 할지, `work_type×disposition` 또는
   `work_type 단순 Top`으로 바꿀지.
3. **처분 결측 라벨** 문구: "미부과·해당없음" 유지 vs "처분 없음(시정요구·통보 등)" 등.
4. **발생분야(sector)**: 92% 미상인데 보조 차트로 남길지, 필터만 둘지, 완전 제외할지.
5. 사례 카드 **기본 노출 건수(20)**·정렬(현재 원본순=대략 최신) — 연도 내림차순 등으로 바꿀지.
6. 면책 데이터 확보 전까지 **안전판 카드 노출 여부**(자리 유지 vs 숨김).
7. 근거법령 **현행 확인** 배지를 F4 조문 뷰어와 연결할지(후속 범위).
