# 디자인: ‘와’ 한 화면 (Situation → Memo)

## 목표
담당자가 “검색했다”가 아니라 **“결재 직전 자료를 얻었다”**고 느끼게.

## 레이아웃 (데스크톱)
```
┌─ 헤더: 감사 선례 도우미 · 면책 고지 ─────────────────┐
├─ 왼쪽 30%: 상황 입력 ─┬─ 오른쪽 70%: 결과 ──────────┤
│ 도메인 [계약▼]        │ [유사 선례 카드들]            │
│ 기관유형 / 업무단계   │  · 품질배지 · 같은점/다른점 │
│ 금액·재원 / 시점      │  · 원문 하이라이트(확보시)   │
│ 자유서술              │ [면책·컨설팅 나란히]         │
│ [선례 찾기]           │ [증빙 목록]                   │
│                       │ [결재용 검토메모 초안]        │
└───────────────────────┴─────────────────────────────┘
```

## 상황 입력 (계약 팩 예시)
- 기관 유형, 업무 단계(기획/발주/변경/검수/대금…)
- 행위 시점, 금액·재원, 예외·변경 사유
- 한 줄 요약 (필수)

## 결과 카드 규칙
- 출처 링크 · 처분/면책결과 · `basis_status` 항상 표시
- **위법 단정 문구 금지**
- `목록만` 배지 건: 메모 근거·증빙 자동생성에 **미사용** (링크만)
- `본문 확보` 이상만 하이라이트·근거 인용

## 검토메모 블록 (복사용)
1. 업무 개요 (상황 입력 반영)
2. 참고 선례 (출처 URL)
3. 적용상 차이 (같은점/다른점)
4. 근거 발췌 (본문 확보 건만)
5. 미확인 사항
6. 담당자 판단 (빈칸)

## 모바일(폰 지시 대비)
상황 폼 상단 고정, 결과는 탭: 선례 | 증빙 | 메모
