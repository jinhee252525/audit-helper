## 2. 핵심 발견 — 데이터 구조 (분류 설계의 전제)

**목록 JSON의 `rtitle` 필드는 두 종류다:**
- **항목형**: `○ …편법 지급(주의, 통보)` 처럼 지적내용 + 처분이 괄호로 표기됨. (파일럿에서 ○ 항목 62개)
- **제목형**: `2025년 산림청 공공기관 안전보건관리 실태 특정감사 결과` 처럼 **감사건 제목만**.

→ **상세 지적·처분의 대부분은 첨부 HWP(감사결과 공개파일 `filedata1`)에 있다.** 목록만으로는 "감사건" 단위까지, "지적 1건=레코드 1건"까지 내려가려면 HWP 파싱이 필요하다.

### ★ 결정 필요 (분류 granularity)
| 옵션 | 레코드 단위 | 장점 | 비용 |
|---|---|---|---|
| **A. 감사건 단위** | 감사보고서 1건 = 레코드 1건 | 빠름, 목록 JSON만으로 가능 | 지적세부유형·처분 정밀도 낮음 |
| **B. 지적 단위(권장)** | 지적 1건 = 레코드 1건 | 스키마 취지에 부합, 검색·대시보드 정밀 | **HWP 파싱 필요**(hwp MCP/라이브러리) |
| **C. 혼합** | 목록은 감사건, 상세는 HWP로 지적 분해 | 점진적 확장 | 2단계 파이프라인 |

## 3-1. 심층 조사 신규 근거 (document-specialist)
- **[표준·실무] 경기도 감사 업무분야별 매뉴얼**(경기도메모리) — `인사 · 지적/부동산 · 건축/주택 · 환경 · 전산`(+예산·계약·시설 추정). 인사분야 15개 세부지적유형 명시 → **finding_type(2차) 근거**. 단 부동산/건축/환경은 **지자체 업무** 성격 → 지자체 소스 확장 시 적합.
- **[핵심] 감사원·국민권익위 「사전컨설팅·적극행정면책 사례집」(2024)** — 사전컨설팅 **6개 유형** 분류(유형명 원문 미확보). `record_type=consult/immunity`(F8)에 직결 → 우선 확보 대상.
- **[부적합·재확인] 지방재정 세출 성질별 분류** = 회계성질 축이라 work_type 아님 → budget_link 보조.
- **[미확보]** 감사원 자체감사 통합매뉴얼·행안부 감사규정(JS/PDF 장벽), 학술(KCI/DBpia) → "확인필요".

## 4. 제안 분류체계 (근거 기반 재구성) ★개정

> 1차안(키워드 빈도만)은 근거가 약해 폐기. **공식 표준 분류를 backbone으로, ALIO 실측으로 보강**한다.

### 근거 조사 결과 (출처별 등급)
- **[표준]** 서울시 투자출연기관 감사사례집 — 실제 감사기구가 지적을 **6분야**로 분류: `인사·조직 / 채용 / 복무 / 예산·회계 / 계약 / 물품`. (출처: news.seoul.go.kr/gov/archives/577531)
- **[부적합]** 정부기능분류체계(BRM) — 정책·사업 축이라 work_type과 결이 다름(오히려 F9 `budget_link` 후보). 감사원법 처분(변상·징계·시정·주의·개선·통보) — 이건 `disposition` 축(이미 반영).
- **[데이터]** ALIO 파일럿 200건 실측 빈도 — 서울 6분야에 없는 빈발 분야: `여비·출장(145) · 공사·용역(106) · 안전·보건(70) · 행사·경비(39) · 정보화(34) · 보조금(27)`.
- **[표준·확인됨]** **감사원 「분야·종류별 감사결과」**(화면 확인) — 두 축을 씀:
  - **분야(정책영역) 11종**: `재정/금융 · 세무 · 산업 · 정보통신/과학 · 건설/교통 · 교육/문화 · 보건/복지/노동 · 외교/안보 · 헌법기관 · 지방행정 · 공직기강 기타`
  - **종류(감사 종류)**: 기관운영·재무·성과·특정·복무감사 등(감사원 감사사무 처리규칙).
  - → 감사원 "분야"는 **정책·산업 영역**(BRM 계열)이라 우리 `work_type`(행정처리 방식)과 **다른 축**. work_type을 대체하지 않고 **별도 상위 필터**로 채택.
- **[확인필요]** 공공감사포털(pap.go.kr) 필터 — 봇 차단으로 미확인.

### ★ 다축(multi-axis) 설계 결론
| 축 | 정체 | 근거 | 스키마 반영 |
|---|---|---|---|
| **work_type** | 행정처리 방식(계약·인사·여비…) | 서울 감사사례집+ALIO | 기존 필드(통제어휘 승격) |
| **policy_field** | 정책·산업 영역(재정/금융·세무…) | 감사원 분야 11종 | **신설 제안**(상위 필터, null 허용) |
| **audit_type** | 감사 종류(재무/성과/특정…) | 감사원 감사사무 처리규칙 | **신설 제안**(null 허용) |
| **disposition** | 처분(변상·징계·시정…) | 감사원법 | 기존 필드(반영됨) |
| **record_type** | 지적/면책/컨설팅 | 스키마 | 기존 필드 |

> 기존 스키마 `work_type`(자유문자열)을 위 대분류 통제어휘로 승격. 소분류는 HWP 파싱(옵션C) 후 확정.

### 축 2 — 지적세부유형(finding_type) : 2차 분류 [HWP 파싱 후 확정]
업무유형별 세부유형은 **옵션 B/C로 HWP를 파싱해야 데이터 근거로 확정** 가능. 현재는 가설:
- `계약 › {수의계약 부당, 분할계약, 과업변경 부당, 입찰 부적정}`
- `인사/보수 › {수당 부당지급, 채용 부적정, 성과급 산정 오류}`
- `여비/출장 › {여비 부당수령, 출장 미실시 청구}`
- `재무회계 › {정산 소홀, 목적외 사용, 세입 누락}`
> ※ 위 세부유형은 **미확정 가설**. HWP 파싱 표본으로 검증 후 확정.

### 축 3~5 — 기존 스키마 유지
`org_type`(기관유형) · `year`(연도) · `legal_basis[].law`(법령) · `disposition`(처분) · `record_type`(지적/면책/컨설팅)

### 부가 축 후보
- **반복도**: (업무유형 × 지적세부유형) 빈도 → 반복지적 Top / 제도개선 발굴(AXIS B)
- **처분 강도**: 변상>징계>시정>주의>통보>개선요구 순 정렬용

## 5. 확인 요청 (HITL-A)

1. **분류 granularity**: → **C 혼합 확정됨**(사용자 확인 완료).
2. **업무유형 대분류(위 10개)**: 이대로 확정할지, 가감할지?
3. **계층 처리**: `채용·복무·여비`를 상위(인사/회계) **소분류로 넣을지**, 아니면 빈발도를 고려해 **독립 대분류로 유지**할지? (여비·출장은 145건으로 빈발 → 독립 유지 권장)
4. **감사원/pap 공식 분류 추가 확인**: 봇 차단으로 미확인 → 로그인된 실제 크롬(Claude in Chrome)으로 감사원 「분야별 감사결과」·공공감사포털 필터를 열어 대조할지?
5. **소스 확장 순서**: ALIO로 축 확정 후 → 국회결산 → 감사원 → 지자체 순 동의 여부.

> 확정되면 → 통제어휘로 `record-tagger` 태깅 → `dashboard-designer`가 대시보드 구성안(HITL-B) 착수.
