# 유형 분류 — 다각적 분석 & 권고안

> 담당: data-analyst / 기준일: 2026-09-05
> 입력: ALIO 전량 2,944건(2021~2026) + 문서 표본 파싱 56건(HWP/PDF/HWPX) + 표준·학술 조사(서울·경기·감사원·권익위)

## 0. 한 줄 결론 (먼저)

> **단일 분류가 아니라 "다축(multi-axis)"으로 가되, 각 축은 "데이터로 실제 채울 수 있는 것"에만 채운다.**
> 주축은 **업무유형(work_type)**, 여기에 **감사종류·처분·법령**을 문서파싱으로 자동 부착(실증 완료), **정책분야(policy_field)** 는 감사원 출처 사례에 한정한 선택축으로 둔다. → 억지 전면부여(무근거)는 하지 않는다.

## 5. 권고안 (의견)

### 5-1. 스키마 축 구성 (직교 다축 + provenance)
> ★ **핵심 설계원칙: "업무 성격(행정행위)"과 "대상 분야(사업영역)"를 분리한다.**
> 한 축에 섞으면 "정보시스템 구축 **계약**"이 계약이냐 정보화냐 모호해짐 → `work_type=계약`, `sector=정보화`로 **둘 다** 기록해 해소.

| 필드 | 역할(차원) | 예시 | 채우는 소스 | 상태 |
|---|---|---|---|---|
| `work_type` | **주축 — 업무 성격(행정행위)** | 계약·인사·여비·회계… | 문서파싱 태깅 | 통제어휘 승격 |
| `sector` | **보조축 — 대상 분야(사업영역)** | 정보화·안전·환경·건축… | 문서파싱 태깅(있을 때) | **신설**(null 허용) |
| `finding_type` | 2차 — 지적세부유형 | 수의계약 부당… | 문서파싱 태깅 | 통제어휘(점진) |
| `disposition` | 처분 | 변상·징계·시정… | 문서파싱 | 기존(정밀화) |
| `legal_basis[]` | 근거법령 (+ `field` 법령분야) | 국가계약법 / 편=재정·경제 | 문서파싱 + 법제처(F4) | 기존(이제 채움) ← **법령 해결** |
| `audit_type` | 감사종류 | 종합·특정·재무… | 문서파싱 | **신설** |
| `record_type` | 지적/면책/컨설팅 | — | — | 기존 |

> `sector`는 권익위 발생분야 28종(§5-2)을 통제어휘로 쓰며, 감사원 「분야」(재정/금융·세무·산업 등 11종)도 여기에 매핑해 흡수(별도 policy_field 불필요). 없으면 null/"미상".

### 5-2. ★ 공식 서식 채택 — 국민권익위 부패공직자 입력서식(구) 분류 (발생분야 × 관련기능 × 세부기능)
> 사용자 제공 자료 = **국민권익위원회 부패공직자 (구)입력서식**의 분류코드. 제가 손으로 만든 서울/경기/ALIO 리스트를 **폐기하고 이 공식 서식을 backbone으로 채택**한다. 권익위 자체 표준이라 **본 과제(권익위·청렴·적극행정)에 정합**하고 상호운용성(권익위 시스템 연계) 우월. 우리가 제안한 "분야 ⊥ 행위" 직교 설계와 정확히 일치.

### 5-2c. `legal_basis[].field` — 법령 분야 (국가법령정보센터 편별 44)
> 근거법령을 **법 분야**로 분류하는 축. sector(발생분야)·work_type(관련기능)과 **또 다른 대상**(=근거법령)에 붙는다. 혼동 금지: 여비 지적의 발생분야는 `01 인사`지만 근거법령(공무원 여비규정)의 법령분야는 `05 국가공무원`일 수 있음.

- 값: 국가법령정보센터 법령체계 44편 (헌법·국회·선거정당·행정일반·국가공무원·법원·법무·민사법·형사법·지방제도·경찰·민방위소방·군사·병무·국가보훈·교육학술·문화공보·과학기술·재정경제일반·내국세·관세·담배인삼·통화국채금융·농업·축산·산림·수산·상업무역공업·공업규격계량·공업소유권·에너지광업·전기가스·국토개발도시·주택건축도로·수자원토지건설업·보건의사·약사·사회복지·환경·노동·육운항공관광·해운·정보통신·외무).
- 채움: **법제처 OC API(F4, 유일 허용 키)** 로 각 법령의 편(field)을 조회해 태그(선택·보조). 문서파싱 단계엔 법령명만 확보.
- **관련 법령 보기(본문 바로 열기)**: 법령명·law_type으로 법제처 딥링크를 **자동 생성**(별도 저장필드 불요) → 클릭 시 본문 바로 열림. 현행성 판정은 하지 않음(담당자가 본문으로 확인).
- 용도: "법령 분야로 필터"(예: 지방제도·재정경제 관련 지적 모아보기). 성긴축 → 필터·보조.

### 5-2b. 결측·대시보드 정합성 원칙 (빈 축 방지) ★
> 다축이라도 대시보드가 "빈칸투성이"가 되지 않도록:
1. **결측은 `null`로 숨기지 않고 "기타/미상" 범주로 명시** → 집계가 항상 100% 합산, 차트에 빈틈 없음.
2. **대시보드 주축(주요 차트)은 "조밀하게 채워지는 축"만 사용**:
   - 조밀축(주축 OK): `work_type`(관련기능) · `disposition` · `year` · `legal_basis` · `audit_type` (문서파싱으로 전건 채움)
   - 성긴축(선택 필터·보조): `sector`(발생분야) — 문서에 분야 근거 없으면 "미상" 버킷, 모수(N) 표기하여 필터로만
3. **각 카드·차트에 모수(N)와 결측률 표기** → 성긴 축을 보더라도 사용자가 신뢰도를 판단.
4. **태깅 실패·저신뢰 레코드는 `review:true`** 로 검수 큐 → 확정 전까지 대시보드 집계에서 분리 옵션.

### 5-3. granularity
- **C(혼합) 확정**: 목록 JSON = 감사건 열거 → 문서파싱 = 지적 1건 단위 분해·태깅. (사용자 확인 완료)

### 5-4. 우선순위 (활용도 기준)
1. **문서파싱 태깅 파이프라인** — 관련기능·세부기능·발생분야·처분·법령·감사종류를 권익위 서식 코드로 자동 태깅(핵심 가치, 실증 완료).
2. 권익위 서식(발생분야28×관련기능19) 확정 → 태깅 → 대시보드(HITL-B).
3. 지자체·중앙부처·감사원 소스 확장 · 사전컨설팅(F8) 후속.

## 6. 남은 확인 (정직)
- **권익위 부패공직자 입력서식** — 구 서식이므로 현행본·개정 여부 확인필요(권익위 내부). 코드값 자체는 사용자 제공으로 확정.
- **사전컨설팅 6유형**(권익위·감사원 사례집) 유형명 미확보 → F8용 별도 확보 필요.
- 감사종류 파싱 **정규화**(PDF 줄바꿈으로 라벨 분절) 보정 필요 — 기술이슈, 해결 가능.
- `sector`(발생분야) 자동 태깅은 문서에 분야 근거가 약하면 "미상" → 억지 부여 금지.

| `org_type` | **기관유형**(중앙·광역·기초·교육·공공기관) |

| `year` | 연도 |
| `added_at` | 수집일 |

### 8-2. 조건부 필수
| 필드 | 조건 |
|---|---|
| `disposition` | 원문에 처분이 있으면 반드시 / 없으면 null(추정 금지) |
| `legal_basis[]` | 원문에 근거법령이 있으면 반드시(+ 법제처 조회 링크 표시) |
| `sector` / `audit_type` | 문서에 근거 있으면 채움, 없으면 null(미상) |
| `immunity.outcome`+`requirements` | `record_type=immunity`이면 반드시 |

### 8-3. 폐기한 것 (사용자 결정)
- **`basis_status`(현행성 판정) 폐기** — 우리가 현행/개정/폐지를 판정하지 않는다. 대신 각 근거법령에 **"관련 법령 보기"**(법제처 본문 **바로 열기** 딥링크: `law.go.kr/법령/{법령명}[/제N조]`, 행정규칙·자치법규는 각 경로)를 붙여 담당자가 클릭 즉시 현행 본문을 확인. 기관 내규(법제처 미등재)는 원문 문서(document_url)로 연결.
- **`tag_method`(자동/사람) 폐기** — 전량 자동이라 불필요.
- **`tag_confidence`·`review`(사람 검수 큐) 폐기** — 사람이 건건 검수하지 않는다. → 대신 §9 "정확도 확보 방법"으로 품질을 담보.

## 9. 정확도 확보 방법 (사람 검수 없이 신뢰도 높이기)

> 사람이 건건 못 보므로, **틀릴 여지를 구조적으로 줄이고 사용자가 즉시 검증**하게 만든다.

1. **통제어휘 강제(closed-set)** — work_type은 관련기능 19코드, sector는 발생분야 28코드 **중에서만** 선택(자유 생성 금지). 엉뚱한 값 원천 차단.
2. **규칙 우선 + AI 보조(2단)** — 처분(괄호 토큰)·법령(「」 인용)은 **정규식으로 결정론적 추출**(기계적으로 정확). AI는 애매한 분류만 담당 → 확실한 건 규칙, 애매한 것만 AI.
3. **원문 앵커 + 원문 노출** — `source_excerpt`(원문 발췌)를 반드시 저장하고, 카드에 **요약 + 원문 발췌를 함께** 표시. 오류가 있어도 담당자가 원문으로 즉시 확인(사람 검수 없이도 자가검증).
4. **골든셋 자동 채점 루프** — 정답 라벨 100건을 만들어, 태깅 프롬프트를 바꿀 때마다 **자동으로 정확도 측정**. 기준(예: 90%) 미달이면 배포 안 함. 건건 검수 대신 **샘플 채점**으로 품질 관리.
5. **자동 게이트(G1·G2)** — 형식·필수필드·통제어휘 위반은 코드가 자동 반려(사람 개입 0).
6. **다중 추출 합의(self-consistency)** — 애매한 분류는 AI에 2~3회 물어 다수결 → 일관성↑.
7. **교차검증** — 같은 사건의 여러 문서(감사결과·조치계획)를 대조, 처분↔지적유형 매핑 규칙으로 모순 자동 탐지.
8. **관련 법령 보기(본문 바로 열기)** — 근거법령 클릭 시 법제처 **본문이 바로** 열림(검색 아님). 현행성은 담당자가 즉시 눈으로 확인 → 우리 판정 부담 제거.
