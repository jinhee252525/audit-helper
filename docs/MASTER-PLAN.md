## 1. 목적·성격
- 감사원·국회결산·중앙부처/지자체/공공기관 자체감사에 흩어진 **지적사례**와 **적극행정 면책·사전컨설팅 사례**를 하나로 모아,
  - (AXIS A) 담당자가 업무 수행 시 유사 지적을 **결재 전에** 확인,
  - (AXIS B) 반복 지적 패턴에서 **제도개선 과제**를 발굴하도록 돕는다.
- 성격: "감사자료 검색기"가 아니라 **상황→선례 매핑** 도구. "하지 마라"가 아니라 **면책사례를 나란히** 두어 "과감히 하되 보호받는 길"까지 제시.
- **AXIS A 성공 기준**: 검색 완료가 아니라 **결재용 검토메모·증빙 초안을 1화면에서 확보**.

## 2. 절대규칙 (품질·신뢰 = 채택 조건)
1. 위법·부당을 **단정하지 않음** (유사사례·근거만, 판단은 담당자/결재권자).
2. 모든 카드에 **출처 원문 링크 + 처분종류**(없으면 "미부과·해당없음") 표시.
3. **근거 없는 사례 생성 금지**(무근거 서술 금지). → 검증에서 환각 0 확인.
4. 근거법령 현행성은 확인 전이면 **"확인 필요"** 명시(임의 현행 처리 금지).
5. **담당자 평가·징계 목적 사용 금지**. 로그·피드백은 품질개선만.
6. 레코드·화면에 **텍스트 품질 배지**(`목록만` / `본문 확보` / `근거 대조 완료`)를 둔다. **본문 미확보 건으로 체크리스트·검토메모 근거를 생성하지 않는다.**

## 3. 데이터 정책
- **"키 없이" = 생성형 LLM 키를 저장소에 심지 않음.** 판정(태깅)은 이 Claude(로그인 세션/서브에이전트) 또는 BYOK로. 공공데이터 오픈API 키(data.go.kr·법제처 OC)는 정상 사용(저장소 커밋 금지).
- **robots.txt 준수.** 허용 소스는 직접 읽기, 금지 소스(감사원 bai·클린아이)는 오픈API/사례집/사용자 직접 다운로드로.
- 저작권 공공누리(특히 감사원·pap 4유형: 변경금지) → **원문 발췌(source_excerpt) 중심**으로 대응(창작 요약 최소화).
- 모든 레코드는 `schema/finding.schema.json` 준수. 원본(raw)은 **별도 보관**해 검증 시 대조 가능하게.

## 5. 분류체계 (의미기반·코드북 폐쇄집합)
- **직교 2축**: work_type(업무유형/관련기능) ⊥ sector(발생분야). 근거 = 국민권익위 부패공직자 입력서식.
- **work_type**: 권익위 19기능(01~19) + **자체감사 특성 신설 20~24**(채권·수입 / 자산·물품·재고 / 시설·안전 / 정보화·데이터 / 문서·기록·정보공개) + **25 교육·학사운영**(학교감사용). (드롭: 내부통제·규정정비=수식어)
- **sector**: 발생분야 28종. **disposition**: 처분(감사원법 등). **audit_type**: 감사종류.
- **분류 원칙**: 키워드가 아니라 **지적의 "의미"를 읽고** 판정. 원문·감사사항명 맥락 활용. **강제분류 금지** — 정말 모호하면 기타(19)+`need_deep`(무근거 배정 금지). 기타는 심층 재분류(deep-pass)로 최소화.
- **행위(지적) 단위 분해**: 1지적=1레코드. 감사원 보고서·pap subList·ALIO 항목·결산 1행 각각 지적 단위. (감사원 과소분해분은 원문 정독 재분해 완료)

## 6. 필수 필드 (완비)
id·record_type·source·source_url·source_excerpt(원문발췌)·org_type·org_name(피감)·audit_org(감사수행)·work_type·year·posted_date(발간일)·added_at(수집일)·document_url·source_title·disposition(null허용)·sector·audit_type. immunity 사례는 `immunity{outcome:인정/불인정, requirements[]}`.

## 7. 중복제거 (확정 규칙)
- 중복 발생 지점: **감사원↔ALIO**, **ALIO↔자체감사**(감독기관이 공공기관 감사한 게 ALIO에도 공시). 국회결산·감사원↔자체감사는 성격 달라 제외.
- 키: 피감기관+지적내용(유사도)+연도. 우선순위 보존: 감사원 > 자체감사(pap 원천) > ALIO(재공시) > 국회결산. 제거내역은 `data/dedup_removed.json`.

## 8. 검증·감독 (환각 0 필수)
- 원본을 findings와 **물리적으로 분리 보관**(raw_docs·inbox) → 언제든 대조.
- **2레인 독립 검증**: ① 검증(pipeline-auditor)이 원본 대조로 무근거·코드북·완비·정확성·중복 확인 → ② 감독(compliance-reviewer)이 **다른 표본으로 재대조**해 검증 자체를 확인. 자기검증 금지.
- 결과: **환각(무근거) 0건** 확인, `validate.py` G1(스키마)+G2(절대규칙) 통과. deep-pass·사례집 반영 후 재검증 1회 수행.
- “환각 0” 주장은 **검증 범위·표본·방식·무근거 건수**와 함께 기록한다.
- 저신뢰/모호는 `review:true`(검수큐) — 사람 전량검수 아님. 심층패스로 자동 축소 + 화면 "검토중" 배지 운영.

## 9. 검색앱·기능 (프론트)
- **규모**: 통합 약 200k 레코드. 정적 단일 JSON 불가 → **검색구조 확정: 방식 A (FlexSearch 인덱스+샤딩)**. 교육 개별학교 필터 기본 숨김. 대시보드 사전집계 JSON. 필요 시 나중에 B(SQLite-wasm) 승격. 참조: `docs/search-architecture.md`, `docs/proposals/2026-09-06-situation-memo/search-architecture-decision.md`.
- **히어로(MVP 출구)**: 상황입력 → 유사선례·적용상 차이(같음/다름) → **원문 온디맨드 하이라이트** → 증빙목록 → **결재용 검토메모** (+면책/사전컨설팅 “보호받는 길”) **한 화면**.
- **‘와’ 포지션**: 업무 상황을 넣으면 1분 안에 검토메모 초안 + 원문 근거 + 보호받는 길이 나온다. (검색기기가 아니라 판단 지원)
- **원문 정책**: 전량 사전수집이 아니라 **온디맨드 확보**. 배지 `목록만` / `본문 확보` / `근거 대조 완료`. 본문 미확보 건으로는 체크리스트·검토메모 근거 생성 금지.
- **F1 유사검색(핵심)**: 담당자가 업무 입력 → **임베딩(의미 벡터)** 으로 유사 지적. 분류 정확도와 독립(임베딩이 담당). 코드필터로 후보 좁힌 뒤 임베딩 랭킹 하이브리드.
- **분류(코드)의 역할**: 필터(계약·인사 등)·통계(AXIS B 제도개선 발굴). 완벽 불필요, "충분+검수큐".
- **MVP(M0) 재정의**: 히어로 1화면 + F1 유사검색 · F8 지적↔면책 대조 · F10 신규 피드. **앞당김**: F3 원문 위치(온디맨드), F4 법령 **링크·확인필요** 최소. F2 체크리스트는 **본문 확보분만**.
- **제외(초반)**: 당시 vs 현재 규정 자동비교; 나라장터·재정·민원 풀연동.
- **제도개선(AXIS B)**: F5/발굴보드는 검색 MVP에 넣지 않고 **대시보드 인사이트**로.
- **도메인 팩**: 계약(1) → 보조금(2). 엔진 공유, 스키마·증빙템플릿·시드만 교체.
- **배포**: GitHub Pages(인터넷망). 공개판 vs 기관용 단계 분리 유지. 업무망 이전은 나중. 프론트 바닐라 우선, 상태는 URL/메모리.
- **디자인**: sage/dusty green matte (`#5B7C73` / `#8DA399` / `#3F5D50`). 레이아웃 = 근거 레인 / 거리 비교 / 메모 독. 태극·국장 금지. 참조: `docs/proposals/2026-09-06-situation-memo/design-system.md`.
