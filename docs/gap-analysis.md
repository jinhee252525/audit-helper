# 가상 시뮬레이션 & 보완사항 (전문 개발자 관점)

> 기준일: 2026-09-05 / 목적: 태깅 파이프라인~운영 배치를 end-to-end로 "돌려본다"고 가정하고, 실제로 깨지거나 빠진 지점을 도출.

## A. 가상 시뮬레이션 (단계별로 돌려보면)

1. **수집(collect_alio)** — 첫 실행 OK(2,944건). 그러나 **매일 배치가 이 스크립트를 그대로 돌리면 매일 3,284건 전량 재다운로드** → 느리고 IP 차단 위험. ❌ 증분 미구현.
2. **문서추출(kordoc)** — HWP 표 복원 검증됨 ✅. 그러나 kordoc은 **Node 패키지** → Python 파이프라인에서 subprocess 브리지 필요, **배치 호스트(VM/클라우드)에 Node+kordoc 설치** 전제. 15MB PDF·스캔본(OCR)은 **느리고 메모리** 이슈. ❌ 런타임 통합·자원 관리 미비.
3. **태깅(tag)** — 처분·법령·원문발췌는 규칙으로 정확 ✅. 그러나 **관련기능(19)·발생분야(28)는 의미 분류라 규칙만으론 부정확** → LLM 단계 필요. 정확도를 **측정할 골든셋이 없음**. ❌ 정확도 근거 부재.
4. **검증(validate G1·G2)** — 동작 ✅. 단 현재 샘플은 새 필수필드(org_name 등) 없어 빨간불(실데이터로 대체되면 해소).
5. **임베딩** — "키 없이" 하려면 **로컬 임베딩 모델**(sentence-transformers 등) 필요 → 설치·모델선택·CPU속도. 브라우저 벡터검색 시 `embeddings.json` 용량(2,944×768≈9MB↑). ❌ 방식 미정.
6. **분석·대시보드** — data-analyst→dashboard-designer(opus) → HITL-B. 데이터 준비되면 진행 가능 ✅.
7. **배포(GitHub Pages)** — 정적 배포 OK ✅. 단 daily 커밋 시 **원격과 충돌**(pull 안 하면) 가능. ❌ pull-before-commit 없음.
8. **운영(daily-updater)** — 조용히 실패하면 아무도 모름. ❌ 실패 알림·모니터링 없음. 클라우드 예약 샌드박스에 **Node/kordoc/네트워크** 되는지 미검증.
9. **공개 리스크** — 감사 원문 발췌를 **공개 GitHub에 재공개** → 개인정보(공무원 성명 등)·저작권 문제 가능. ❌ PII 마스킹·재공개 근거 미확인.

## B-3. 수집 거버넌스 (robots.txt 준수) ★ 신규
- **원칙**: 수집 전 소스 robots.txt 확인. `Disallow: /`면 **스크래핑 배제**.
- ALIO=허용(수집 정당) · **감사원·클린아이=금지 → 공식 오픈API/공공데이터셋(data.go.kr) 또는 허가 경로만**.
- **키 정책(확정)**: "키 없이"의 뜻은 *프로젝트에 생성형 LLM 키를 심지 않는다*임(판정용 LLM은 Claude Code 또는 **BYOK 운영자 키**). **공공데이터 오픈API 키(data.go.kr·법제처)는 정상 사용** — 정책 예외가 아님. 따라서 감사원·클린아이는 **공식 오픈API로 수집(무료 공개키)** 이 정답.
- 어댑터는 요청 간 간격·백오프·User-Agent 명시(정중한 수집).
